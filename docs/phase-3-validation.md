# Phase 3 validation — display extraction

Implemented on 2026-09-14 from merged Phase 2 commit `54f2fdd` in the isolated `codex/phase-3-display` worktree. The shared checkout's uncommitted Wi-Fi/install/skill changes are excluded.

## Why and scope

Image transforms and Linux renderer effects previously shared one Linux-only file. `internal/display` now owns portable decode/crop/grayscale/rotation and the platform rendering adapters. `internal/trmnl/render.go` retains the old call site, maps effective configuration, and supplies the unchanged command runner. The cycle still owns refresh cadence.

No existing exported Go surface, CLI behavior, JSON field/default, stored path, or file format changes. Prepared output remains PNG; raw downloaded bytes still determine the hash. No migration is required. PNG creation, inherited environment, command order, error text/wrapping, and non-Linux unsupported behavior are preserved.

## Behavioral evidence

The [pixel corpus](../internal/display/testdata/README.md) was generated with Go 1.26.2 on Linux from the original rendering functions at `54f2fdd`, before extraction. Fourteen cases cover landscape/portrait, center crop, up/down scaling, software quarter-turns, alpha, and PNG/JPEG/GIF/BMP input. Tests compare dimensions and every decoded RGBA pixel; a separate primary-color assertion checks legacy luminance values. Fixtures are checked in and never regenerated by tests.

Linux module tests verify partial/full/custom commands, all rendering options, repeated placeholder expansion, environment additions, and depth/rotation/render failures. They assert that the expected prepared pixels are on disk before each command, including failing commands. Decode failures preserve the prior file; write failures run no commands; overwriting preserves existing file permissions. Unsupported framebuffer rotation remains best effort.

Facade tests use isolated fake executables with the existing process runner to check default/configured argument mapping, inherited versus overridden environment, exact process error text, and the same pixel corpus. Non-Linux module and facade tests retain the unsupported error without preparing or writing an image.

The new facade tests and existing full `internal/trmnl` suite also passed with race detection against an untouched temporary copy of the pre-extraction production source, on both macOS and Linux. This checks that the assertions describe legacy behavior. The temporary baseline implementation is not included in the repository.
